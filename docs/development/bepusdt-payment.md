# BEpusdt 独立支付网关

BEpusdt 负责收款、链上确认和支付通知；new-api 创建钱包充值订单、核对付款并增加额度。首期仅支持预先确定金额的钱包充值，计价币种固定为 USD，支持 USDT、USDC。BEpusdt 收银台负责提供它已配置的可用网络、汇率及实际转账金额。

## 配置

1. 单独部署 BEpusdt，配置收款钱包、网络、汇率和 API Token。准备可被用户及 new-api 访问的 HTTPS 地址。
2. 在 new-api 系统设置中确认服务地址为公网 HTTPS 地址。若填写了支付网关的自定义回调地址，确认它同样指向这套 new-api 服务。
3. 进入「系统设置 → 计费与支付 → 支付网关 → BEpusdt」。填写网关地址（站点根地址）、API Token、每单位额度的 USD 价格、最低充值额度和允许币种。
4. 完成现有支付合规确认，并主动打开「启用 BEpusdt 支付」，保存设置。只保存地址和 Token 不会显示支付入口。
5. 用户从钱包选择金额和 BEpusdt，确认 USD 应付金额后在弹窗中打开收银台，钱包页面继续查询订单状态。关闭弹窗后可通过「继续付款」重新打开同一订单；收银台不能内嵌时可选择「在新标签页中打开」。链上确认后收到有效通知才到账，跳转回钱包本身不会增加额度。

API Token 不返回前端；输入框留空保存会保留旧值。关闭开关仅停止创建新订单，已有订单仍可结算。存在待处理订单时保留原 API Token 与原网关服务，避免中途轮换密钥。当前没有多密钥轮换机制。

## 金额与到账

- 一单位额度代表系统基础美元额度单位（通常为 500000 quota）。最低充值和单价均以此为基准，不随页面显示币种改变。
- 与 LDC 共用充值金额档位时，将最低充值额度设置为相同值；LDC 积分价格与 BEpusdt 的 USD 价格分别配置，不直接将积分当作 USD 使用。
- 应付 USD = 充值额度单位 × BEpusdt 单价 × 用户组充值倍率 × 金额折扣，最终四舍五入到两位小数。使用现有充值金额选项和折扣配置。
- 后端计算价格，不接受浏览器提交的应付金额。订单创建时冻结应付美分数和待到账 quota，后续修改单价或 QuotaPerUnit 不会改变该订单的到账量。
- 当前只接受整单位额度。TOKENS 显示模式下，输入必须为 QuotaPerUnit 的整数倍。
- BEpusdt 显示的链上金额可能因汇率或订单匹配规则略有差异，用户以收银台的币种、网络、地址及金额为准。
- 订单有效期为 15 分钟；过期后收到经核验的真实付款仍可到账。钱包余额上限校验失败会保留未结算状态并返回失败，以便后续重试和管理员核查。

## 接口与支付复核

- 报价：POST /api/user/bepusdt/amount（登录后）
- 创建订单：POST /api/user/bepusdt/pay（登录后，限制高频下单）
- 查询自己的充值结果：GET /api/user/bepusdt/orders/:trade_no
- 异步通知：POST /api/bepusdt/notify（公网可达，按 BEpusdt 协议验签）
- 支付返回：/wallet?bepusdt_order=BEP-...

new-api 验证 MD5 签名、订单号、上游交易号、精确金额及状态，并在首次到账前向 BEpusdt 再核对已支付状态。事务内锁定订单与余额，只允许成功充值一次。重复和并发通知不会重复加额度，待支付、确认中、过期、取消和确认失败通知都不会加额度或覆盖已成功状态。失败通知返回非 200，让 BEpusdt 重试。

支付复核针对本地核对版本 BEpusdt main 0716485（2026-10-19）：其 POST /api/v1/order/create-order 对相同商户订单号的待支付、确认中和成功订单返回原订单。因此复核会携带冻结的金额及回调参数，重新签名请求同一订单，并要求返回状态为 2、USD 金额及上游交易号完全一致。不是再次生成新的商户订单号。

不要把 /api/v1/pay/info 当作商户后端查单接口：该版本会绑定收银台访客指纹。升级 BEpusdt 时必须重新验证 create-order 的幂等返回契约；如果上游新增签名查单接口，应迁移到该接口后再升级。

## 数据库与升级

新增 bepusdt_orders 表，保存充值订单的金额、quota、上游交易号及回调参数快照，关联原有 top_ups.trade_no。上游交易号允许为空，绑定后具有唯一约束。没有删除或改写旧充值记录。

上线前备份数据库，并按 DEVELOPMENT_WORKFLOW.md 审核数据库迁移和恢复方案。使用 upgrade.sh 时本次属于数据库相关变更，需要完成兼容性审核后显式允许数据库变更。应用回滚时保留此表及原充值记录；旧版本不能处理 BEpusdt 通知，必须先停止新下单并妥善处理在途付款。

## 范围与验证

BEpusdt 独立于 Epay、Linux Do Credit、Stripe、Waffo 等已有网关。钱包充值到账后可继续使用现有余额支付；不提供 BEpusdt 直接订阅购买、自动退款或反向扣款。

自动化验证包含签名篡改、金额和订单绑定、已签名但未支付的拒绝、重复及并发回调、关闭后的旧订单到账、超限失败重试、管理员补单、用户隔离，以及 SQLite / MySQL / PostgreSQL 的首次和重复迁移。浏览器检查使用隔离的模拟接口，不涉及真实转账。

上线启用前仍需使用自有网关完成一笔小额真实链上支付，确认公网通知可达、实际币种网络与汇率、自动重试以及余额到账。当前本地验证不能替代真实链上验收。
